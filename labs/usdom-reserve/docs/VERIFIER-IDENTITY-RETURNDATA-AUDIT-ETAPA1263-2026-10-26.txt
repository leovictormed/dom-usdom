ETAPA 1263 — verifier identity returndata audit
Date: 2026-10-26

Scope
-----

Adversarial review of verifier configuration and capability reads after
deployment, including deposit admission, checkpoint candidate creation, pause/
resume identity checks and exact restoration. Proof-result and RISC Zero adapter
boundaries were rechecked alongside the prior Safe, token and registry evidence.
No Rust, production script, network, signing, deployment, funds, commit or push
operation was performed.

Result
------

No new material production defect was found. Reserve and Registry bind verifier
runtime code, nonzero configuration hash and an exact flow-specific acceptance
capability at construction, then reread all three before relevant state
transitions. The shared scalar decoder copies only 32 bytes under a fixed gas
cap and accepts only an exact 32-byte return.

A malformed reserve configuration getter reverts through the constructor-safe
`InvalidConfiguration` path, while a malformed capability becomes a mismatch and
reverts `VerifierChanged`. Registry normalizes either malformed identity getter
to a verifier mismatch. These diagnostic differences do not permit state
movement: no deposit identifier, collateral credit, candidate, proof debt or
resume authorization is consumed.

The actual proof-result boundary remains independently strict: Reserve and
Registry require an exact one-word capability magic, while RISC Zero adapters
require the underlying verifier's void call to return exactly zero bytes. Short,
trailing, oversized, false, wrong-domain and return-bomb results are already
covered and fail atomically.

Regression expansion
--------------------

Both mutable verifier mocks now independently emit the following responses from
their configuration and capability getters after successful deployment:

- 31-byte short response;
- 33-byte response with trailing data; and
- one-megabyte return bomb.

New Reserve and Registry regressions exercise all six modes. Reserve proves no
deposit is consumed; Registry proves no candidate is created. Restoring exact
responses permits the original deposit/candidate operation without changing its
identifier or statement. Production contracts and ABI were unchanged.
