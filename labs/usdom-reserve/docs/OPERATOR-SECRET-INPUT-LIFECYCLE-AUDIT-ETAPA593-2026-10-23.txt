USDOM — operator secret-input lifecycle audit — stage 593
Date: 2026-10-23

Scope
=====
Audited operator-facing password, passphrase, TPM owner authorization, RPC token,
provider credential, recovery material, mnemonic/seed and signature ingress via
TTY, stdin and owner-only files. Reviewed echo/history behavior, inherited xtrace,
argv/environment exposure, temporary permissions, normal cleanup, heap erasure and
core/backtrace artifacts. No real secret file was opened.

Findings corrected
==================
1. `prepare-native-receiving-wallet.sh` used silent reads but did not require an
   actual terminal. It now refuses redirected stdin/stderr before either backup
   passphrase read. Its existing no-echo reads, two-entry comparison, tmpfs 0700
   directory, 0600 password file, variable unsets and cleanup remain enforced.
2. Three token-bearing Node operators were exposed directly through package
   scripts. Unlike the hardened shell entrypoints, a Node crash could therefore
   inherit core-dump policy and the token-bearing process had no xtrace wrapper.
   A fixed allowlist launcher now disables xtrace and trace fd inheritance,
   suppresses Rust backtraces, requires `ulimit -c 0`, sets umask 077 and then
   execs exactly one of the issuance/genesis/block operators. Each Node program
   refuses accidental direct execution outside that launcher.
3. Those three Node operators retained owner-only RPC-token Buffers (and two
   other inputs explicitly classified private) until process teardown. They now
   track every initial and TOCTOU-recheck secret buffer and overwrite it in a
   `finally` block on success or error.
4. The standalone deterministic wallet bootstrap loaded its password into an
   ordinary String. Other native USDOM operators already moved passwords into
   zeroizing wrappers. Bootstrap now immediately moves the loaded password into
   `Zeroizing<String>` so normal and error drops erase its allocation.

Confirmed properties
====================
- All nine shell entrypoints with hidden secret prompts disable inherited xtrace,
  Rust backtraces and core dumps before capture and require interactive stdin and
  stderr. Password and TPM variables are unset immediately after owner-only
  tmpfs files are created and again by cleanup where applicable.
- Shell `read -s` prevents terminal echo; scripted reads do not enter interactive
  shell history. No password, TPM authorization, mnemonic, recovery seed, RPC
  bearer or provider URL is placed in argv or exported as a literal environment
  value. Child processes receive only paths to protected files or anonymous stdin.
- Secret directories are mode 0700 on `/dev/shm`; umask 077 applies before file
  creation, so the subsequent chmod 0600 does not leave a permissive creation
  window. Rust readers reject symlinks, hardlinks, foreign ownership, excessive
  modes, replacement, invalid UTF-8 and oversized inputs.
- Recovery phrases are generated in-process and durably written create-only to
  an owner-only file. They are never printed. Signature files contain public
  authentication artifacts rather than signing secrets, but remain bounded and
  owner-only throughout local ceremonies.
- JavaScript must retain one immutable bearer-token string while constructing an
  authenticated local HTTP request; the hardened launcher prevents core artifacts
  and the mutable source buffers are erased in `finally`.
