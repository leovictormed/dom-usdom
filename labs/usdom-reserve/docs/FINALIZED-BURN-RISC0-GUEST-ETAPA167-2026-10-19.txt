Finalized-burn RISC Zero guest — Stage 167
Date: 2026-10-19
Status: isolated implementation and reproducible build; no deployment, funds,
        production activation, commit or push

Outcome

The portable UDFINL02 finalized-burn relation now has a concrete RISC Zero
guest. The guest reads one bounded private byte string, executes
dom-usdom-finalized-burn-program::execute and commits exactly the unframed
32-byte Solidity-compatible statement hash. It has no filesystem, network,
clock, process or arbitrary host-call authority.

Pinned backend and security boundary

- risc0-zkvm is pinned exactly to 3.0.6 with default features disabled.
- The guest uses the reviewed `std` guest profile only.
- RISC Zero 3.0.3 was the first 3.x release containing the fix for
  CVE-2025-61588; 3.0.6 is therefore above the fixed floor. The advisory is:
  https://github.com/risc0/risc0/security/advisories/GHSA-jqq4-c7wq-36h7
- The checked lock selects risc0-binfmt 3.0.5 and risc0-zkvm-platform 2.2.3.
- Input length is checked before allocation and cannot exceed the portable
  relation's MAX_FINALIZED_BURN_PROVER_INPUT_BYTES.
- Invalid decoding, burn inclusion, checkpoint finality or cross-domain binding
  panics the guest before a successful receipt can exist.
- The journal contains only the relation's 32-byte public output.

Executed checks

- real RV32IM guest compilation under the digest-pinned Docker builder;
- byte-for-byte second-build reproduction;
- R0BF framing, user/kernel payload and artifact SHA verification;
- Cargo manifest, complete lock copy and exact RISC Zero dependency versions;
- real r0vm rejection of zero-length input before allocation;
- real r0vm rejection of declared input above the fixed limit;
- real r0vm rejection of a malformed one-byte UDFINL02 payload;
- source policy ensuring the exact length check, portable execute call and raw
  32-byte journal commit remain present.
- native Cargo test/benchmark harness exclusion, because executing zkVM guest
  syscalls as a Linux process is invalid and previously caused a host abort.

Open production gates

There is no positive raw Ethereum checkpoint witness for this relation yet.
The existing opaque VerifiedCheckpoint unit fixture cannot substitute for a
Beacon-finalized registry receipt/account/storage witness. Therefore the valid
path has not been executed or cycle/memory benchmarked inside RISC Zero.

A RISC Zero receipt has not been generated, compressed for Ethereum or checked
by an immutable Solidity verifier. The verifier manifest remains unconfigured,
the separate checkpoint consensus-extension prover is absent, production chain
identities are unratified and no independent review has assessed the guest or
its verifier. Closed-mainnet and real-funds gates must remain closed.
