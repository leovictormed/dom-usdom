ETAPA931 — RUST SECRET BUFFER ZEROIZATION
Date: 2026-10-23

Focused classification
- Thirteen plaintext credential/key/private-payload acquisition boundaries were
  identified in the DOM operator binaries. Ten were already protected: seven
  UTF-8 password/recovery/token loaders use the corrected shared zeroizing
  loader, and three TPM owner-auth/authorization buffers use Zeroizing or a
  zeroizing domain type.
- Three ordinary Vec allocations remained: the spend proving key in private-
  burn construction and the same private-burn payload in TPM bootstrap and DOM
  submission. These are the largest repeated missing-erase family.
- Public Ethereum/checkpoint witnesses, hashes and commitments are not secret
  credentials. Encrypted wallet snapshots remain ciphertext buffers. Proof-host
  private inputs are bounded internal buffers behind fixed diagnostics and are
  a distinct high-volume lifecycle family, not silently counted as protected.

Correction
- All three plaintext Vec values are now wrapped immediately in
  Zeroizing<Vec<u8>>. Deref-based parsers/hash checks see identical bytes, while
  normal return and every `?`/error unwind erase capacity on Drop.
- Result for the focused plaintext family: 13/13 protected, 0 ordinary
  plaintext key/auth/password/private-payload allocations remaining.

Validation
- Structural regression passes 1/1; rustfmt and diff-check pass. No Cargo
  build, key, password, wallet, TPM, proof or external operation was executed.
