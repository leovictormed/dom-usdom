Problem closed
--------------
The release still required the operator to supply four deployer addresses,
four nonces and four predicted CREATE addresses. Manual entry can reorder
dependencies, reuse a nonce, select a busy account or bind the release to an
address already occupied on mainnet.

Implementation
--------------
`npm run --silent materialize:mainnet-deployment-identity` now performs the
entire public derivation without accepting arguments:

- reads the deployer twice from the connected Ledger without requesting a
  signature;
- requires two distinct HTTPS RPC URLs and chain ID 1;
- requires the deployer to be an EOA and its pending nonce to equal its
  finalized nonce on both sources;
- requires both sources to agree on that nonce;
- derives four consecutive CREATE addresses in dependency order: finalized
  burn verifier, checkpoint verifier, checkpoint registry and reserve;
- rejects collision with the token, configured administrative roles, another
  planned contract, or any address containing finalized code;
- refuses any pre-existing release field that differs from the derivation;
- preserves `productionReady=false` and `realFundsAuthorized=false`;
- rereads the source configuration after all network observations and writes
  through the locked, fsync-backed configuration boundary.

The two finalized observations are stored in the owner-only control evidence
directory without endpoint URLs. Provider failures are converted to fixed RPC
1/RPC 2 messages so an API key embedded in a URL cannot reach logs.
