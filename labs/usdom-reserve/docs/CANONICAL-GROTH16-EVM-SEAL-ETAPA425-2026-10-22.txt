USD-native / USDOM — Stage 425: canonical Groth16 EVM seal boundary
Date: 2026-10-22

Finding
=======

The production RISC Zero adapters accepted selector-prefixed proofs between
four bytes and 64 KiB. The Rust packagers emitted a four-byte verifier selector
followed by the canonical eight-word BN254 Groth16 seal, but the Solidity and
JavaScript boundaries did not require that exact representation. This allowed
locally authenticated packages whose length differed from the only format the
pinned RISC Zero Groth16 verifier is expected to consume.

Correction
==========

The finalized-burn and checkpoint adapters now require exactly 260 bytes:

  4-byte RISC Zero verifier selector + 8 * 32-byte BN254 words.

Both Rust EVM packagers verify that exact size before publishing a seal. Both
JavaScript submission builders, serialized-package validators and artifact
collectors enforce the same boundary. The finalized-burn capacity executor
also rejects any noncanonical seal before measuring or exercising the EVM
path. Truncated and extended packages are rejected even when their index,
length and SHA-256 metadata are internally consistent.
