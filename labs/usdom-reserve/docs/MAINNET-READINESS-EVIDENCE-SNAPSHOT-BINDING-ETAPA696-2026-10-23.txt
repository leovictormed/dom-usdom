ETAPA 696 — aggregate readiness evidence snapshot binding
Date: 2026-10-23

Finding
=======
The aggregate mainnet-readiness checker first read each configured evidence file to
compute evidenceFiles[path], then independently read JSON evidence again for semantic
validation. A concurrent replacement between those reads could make the readiness
assessment bind SHA-256 for bytes A while validating object B.

Correction
==========
The checker now captures every configured evidence file once in an in-memory byte
snapshot. Its SHA-256 inventory and all optional evidence JSON, verifier configuration
manifests, and native attestations consume that same Buffer. Missing snapshots fail
closed through the existing null/assessment path. Raw fork-rehearsal evidence already
hashed and parsed the same local Buffer and remains unchanged. The native manifest
child checker independently receives and enforces the expected SHA-256.

Secondary-boundary audit
========================
- The native runtime child stdout is a bounded line protocol parsed with duplicate-field
  rejection; it is not JSON authority.
- Runtime RPC secrets are read through runtime-secret-json from an owner-only path with
  fatal UTF-8/strict JSON; literal secret JSON in the environment remains forbidden.
- RPC observations remain delegated to the bounded strict provider SDK and consensus
  collectors.
- Forge/git stdout and Solidity source text are not parsed as JSON authority. Git binary
  diff output uses NUL framing; signed-tag output is processed by the dedicated signature
  fingerprint parser.
