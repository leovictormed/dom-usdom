USDOM hardening stage 384 — shared secret and wallet-state reads

Date: 2026-10-22

The node secret-file boundary now delegates owner-only reads to the common
descriptor-anchored reader in dom-wallet-crypto. This removes a second copy of
pathname validation logic and enforces the same retained mode-0700 parent,
openat/no-follow child capture, mode-0600 current-owner single-link policy,
bounded read and post-read identity audit used by the wallet and RPC tooling.

Finalized-deposit registration and observation now use that shared reader for
private seals, snapshots and registration state. Public evidence remains on
the bounded captured-file path because it deliberately has a different
permission policy. The recovery command already used the shared reader for its
passphrase and retains captured reads for public witnesses.

- dom-node focused secret-file tests: 2/2 passed, including symlink, hard-link,
  permissions and size rejection;
- seven affected native USDOM/operator binaries compile together with the
  native-usdom-v4-poc and usdom-wallet-operator features;
- operator runbook regression: 63/63 passed;
- proof-program boundary self-test and manifest verification passed after the
  intentional source digest refresh;
- complete deterministic source manifest was regenerated and verified.

The running finalized-burn capacity proof was not restarted. It retains its
already-loaded pre-stage executable, so its result is capacity evidence; the
final source-bound release proof must be generated after source stabilization.
