Findings corrected
------------------
1. Ethereum reads could be taken from independently moving finalized heads.
   The executor now requires both RPCs to identify canonical Ethereum mainnet
   by genesis and to agree on the exact finalized number, block hash, timestamp
   and base fee. All contract reads use that numeric snapshot, whose hash is
   rechecked after the reads.
2. Chain ID alone did not bind the deployed authorities. Both RPCs now prove the
   release-pinned Reserve and token runtime code hashes and Reserve configuration
   hash at every consensus snapshot. Any mismatch stops before signing/publish.
3. The signed transaction validator accepted an otherwise exact transaction
   signed by a different account. It now requires the recovered sender to equal
   the package's burn recipient. The shell also retains Ledger-address equality.
4. A pre-existing payout baseline accepted any decimal proved-debt value. It now
   requires exactly 1,000,000 base units. New baselines record the exact finalized
   block number/hash; payout validation and final execution evidence require
   well-formed snapshot identities.
5. The executor created terminal payout evidence without invoking its semantic
   validator. A dedicated checker now recomputes the baseline SHA-256 and checks
   exact recipient, Reserve, released, outstanding and proved-debt deltas before
   the execution artifact can be installed.
6. The final signing and publication checks now refresh the shared finalized
   snapshot before nonce/state/deadline decisions, closing stale-snapshot use.
