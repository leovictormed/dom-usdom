ETAPA810 — CREDENTIAL CHILD ENVIRONMENT
Date: 2026-10-23

Finding and correction
----------------------
The two credential-bearing Node launchers pinned the executable but inherited
the complete operator environment. Variables such as `NODE_OPTIONS`,
`NODE_PATH`, `NODE_DEBUG` or `SSLKEYLOGFILE` could inject code or persist network
secrets before application validation; unrelated bearer/password variables were
also unnecessarily visible to the child.

Both launchers now pin `/usr/bin/env` by path, owner, link count, mode, inode
metadata and SHA-256, recheck it, and launch with `env -i`. Issuance/genesis/miner
receive only `HOME` and the non-secret launcher marker. Checkpoint observation
receives only the owner-only RPC catalog pathname. Node is still absolute and
pinned; neither child spawns another process or needs PATH.

Validation
----------
Structural and modeled hostile-environment tests verify the exact allowlists and
absence of Node/profiling/bearer injection variables. Launcher suites pass 8/8;
both scripts pass `bash -n`; `git diff --check` passes. No child, RPC, issuance,
observation or funds operation ran.
