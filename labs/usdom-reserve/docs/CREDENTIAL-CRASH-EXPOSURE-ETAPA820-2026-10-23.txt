ETAPA 820 — crash, tracing, argv and environment exposure
Date: 2026-10-23

Finding
=======
The shared release/native Ledger signer held signature material in shell memory
without disabling core dumps. The finalized-deposit witness builder likewise
processed private witness bytes without disabling cores or inherited xtrace.
The thin release/native wrappers could emit their delegation command under an
inherited `bash -x` session before the shared signer disabled tracing.

Correction
==========
The signer and witness builder now fail closed unless `ulimit -c 0` succeeds,
before any sensitive input or child. Both also disable xtrace and detach
`BASH_XTRACEFD`; the two wrappers do so before delegating. The zero core limit is
inherited by Ledger/Node/Cargo children.

Inventory results
=================
- All eleven memory-bearing credential/ceremony cores now stop xtrace, detach
  its fd and fail closed on core-limit setup.
- Recovery passwords and TPM owner authorization remain shell-local only, are
  immediately written to owner-only tmpfs files, unset, and supplied to native
  binaries by pathname. They are never exported or placed directly in argv.
- Bearer tokens and raw transactions are likewise passed as validated file
  paths; secret contents are not environment values or command arguments.
- Noninteractive Bash does not persist command history. No script enables
  history or writes a HISTFILE.
- Linux same-UID ptrace policy is host/kernel policy. No shell-only toggle can
  reliably make an already running Bash process non-dumpable across exec; this
  stage therefore does not claim ptrace isolation. It removes durable crash
  artifacts and avoids argv/environment copies without requiring privilege.

Validation
==========
- Structural/local hardening suite and descriptor/environment regressions:
  13/13 pass.
- Local `bash -x` harness proves a post-hardening sentinel is absent from stderr
  and a child observes core limit zero.
- bash -n: thirteen affected credential/ceremony entrypoints pass.
- git diff --check: pass.

No Ledger, RPC, TPM, Cargo build, signing, deployment or transmission ran.
