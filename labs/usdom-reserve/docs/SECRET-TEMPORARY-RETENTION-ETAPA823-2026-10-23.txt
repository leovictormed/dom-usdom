ETAPA 823 — secret temporary retention and signal cleanup
Date: 2026-10-23

Finding
=======
The native receiving-wallet flow stores the wallet passphrase, recovery backup
snapshot and private identity snapshots in a 0700 /dev/shm directory. Its trap
used PATH-resolved `rm`/`rmdir`, did not preserve exact HUP/INT/TERM status and
could leave nested or newly introduced temporary files behind when `rmdir`
failed. This was the largest remaining code-controlled retention gap in the
credential/signing/witness inventory.

Correction
==========
The flow now pins Node by direct-file ownership, mode, link count, directory,
inode metadata and SHA-256, rechecks it before every authority read/install, and
uses that pinned runtime for one recursive cleanup of the constrained tmpfs
directory. Cleanup unsets both passphrase variables, disables recursive traps,
removes every residual nested file and exits with exact EXIT/HUP/INT/TERM status.

Inventory and limits
====================
- Wallet/TPM/burn/witness/signing/executor secrets use owner-only /dev/shm trees
  with EXIT/HUP/INT/TERM cleanup. Proxy stdout/stderr stay inside those trees and
  only fixed redacted diagnostics reach the operator.
- No credential flow invokes logger/systemd-cat or writes a persistent log.
- SIGKILL and host power loss cannot run userspace traps. tmpfs avoids ordinary
  filesystem persistence but can be swapped by host policy; guaranteeing
  encrypted/disabled swap or locked pages requires host/native-runtime support
  and is not falsely claimed by this shell correction.

Validation
==========
- Focused cleanup/crash/descriptor suites: 11/11 pass.
- Local TERM harness proves nested secret deletion and exact status 143.
- bash -n and git diff --check pass.

No real secret, Ledger, TPM, RPC, signing, deployment or fund operation ran.
