USDOM Stage 1091 — exact Safe v2 keystore command generator
Date: 2026-10-26
Scope: static/lightweight Bash and Node validation; no key generation, secret read, network, signing, deploy, Forge, Cargo, commit or push

Result
------
The closed-mainnet generator now emits one complete command sequence for the
Safe v2 owner ceremony without address placeholders. Running the emitted
program interactively creates nine encrypted keystores: primary, secondary and
recovery for governance, reserveGuardian and checkpointGuardian.

Security properties
-------------------
- uses the pinned /home/leonardov/.foundry/bin/cast after the toolchain check;
- `cast wallet new ... --password` obtains each distinct password through its
  hidden terminal prompt; passwords, seeds and private keys never enter an
  environment variable, command argument, stdout or the public bundle;
- private and backup directories are mode 0700; every encrypted keystore and
  backup is current-user mode 0600, a regular non-symlink, single-link file;
- creation is resumable and create-once: existing keystores are reused only
  after structural checks, while `--force` and unsafe-password modes are absent;
- backup copies use no-clobber and no reflink, must have a different inode and
  identical SHA-256 content;
- all nine addresses are extracted only from the encrypted JSON public address
  member and checked for global uniqueness;
- the private identity document and public import bundle are byte-identical
  `usdom-safe-owner-identities/v2` documents using ownersByRole;
- public output contains only the public JSON bundle and its labels.

Operational limit
-----------------
The local backup directory protects against accidental alteration, not loss of
the machine. It must be copied to offline media before deployment. Local
keystores also preserve single-operator control; broader funds require migration
to separate hardware/device custody.
