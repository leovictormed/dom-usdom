Remaining native monetary boundary
The current native source search found no USDOM transaction/issuance/burn
implementation. Search alone is not proof: the actual prototype documentation
also explicitly identifies this integration as unimplemented. Production work
must define and enforce, in all consensus validation paths:
1. An authenticated deposit identity binding chain, token, reserve, event,
   recipient commitment and amount; durable replay protection for issuance.
2. USDOM state/proofs committed by canonical DOM blocks, conserving credited
   supply and enforcing unique nullifiers and redemption request identities.
3. Atomic connect/disconnect, persistent state and crash recovery for issuance,
   spends and burns. Wallet or RPC-only checks cannot enforce consensus rules.
4. Burn evidence binding every EIP-712 field and the supported remote checkpoint
   policy, with revalidation after reorganizations and replay protection across
   deployments and chains. Historical paid obligations must survive recovery.
5. Ethereum-verifiable DOM proofs, now explicitly required by the operator.
   Quorum remains prototype-only. Native asset/privacy design and the precise
   finality/proof mechanism still need implementation and validation; a quorum
   adapter cannot satisfy this requirement. See NATIVE-USDOM-DESIGN.txt.
6. Explicit activation/network-version policy and tests for initial sync,
   competing histories, database recovery and independent nodes. This additive
   prototype import does not activate any new monetary/consensus rule.
