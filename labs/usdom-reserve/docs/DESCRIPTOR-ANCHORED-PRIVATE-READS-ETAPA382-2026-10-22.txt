USDOM stage 382 — descriptor-anchored private reads
Date: 2026-10-22

Finding
=======

The RPC bearer-token and recovery-passphrase loaders checked private pathname
metadata and then opened by path. Their post-open checks were strong, but the
lookup itself did not remain anchored to the authenticated parent descriptor.

Correction
==========

dom-wallet-crypto now provides read_private_bytes. On Unix it retains the
exact current-user mode-0700 parent, opens the child descriptor-relatively with
O_NOFOLLOW and O_CLOEXEC, requires a current-user mode-0600 single-link regular
file, enforces a caller bound before and during allocation, reauthenticates the
file and parent after capture, and returns a zeroizing byte buffer.

The RPC token and offline recovery password loaders use this boundary before
UTF-8 parsing and their existing semantic validation. No secret is added to an
argument, environment variable, log or durable evidence file.

Validation
==========

- shared bounded direct/symlink/hard-link reader: 1/1 passed
- RPC owner-only token test with rpc-client: 1/1 passed
- recovery password permission/symlink test: 1/1 passed
- formatting and repository whitespace checks pass
