USDOM stage 569 — secret logging, process and crash-artifact audit
Date: 2026-10-23
Scope: production DOM node/RPC, native USDOM wallet operators, TPM/recovery
       ceremonies and finalized-deposit source collection.

Confirmed findings and corrections

1. Finalized-deposit provider credentials crossed the process environment.
   The interactive wrapper exported USDOM_FINALIZED_DEPOSIT_SOURCES before
   starting Node. Cataloged HTTPS endpoints can contain provider API keys in
   their path/query, and a reusable environment value may be exposed through
   same-UID /proc process inspection or service diagnostics.

   The wrapper now disables xtrace/core dumps and sends the bounded JSON only
   through an anonymous stdin pipe. The collector no longer reads that
   environment variable, enforces a 64-KiB input cap, clears the captured byte
   buffer, and retains endpoint-aware error redaction. No endpoint reaches argv,
   environment, filesystem or report serialization.

2. Standalone RPC still accepted DOM_RPC_TOKEN itself from the environment.
   That compatibility path was removed. Embedded callers pass the token
   directly; standalone callers use the already-hardened owner-only file. The
   desktop documentation now describes its actual direct in-process handoff.

3. The node and dom-wallet-rescan still accepted the WalletDir password in
   DOM_WALLET_PASSWORD. Both now fail closed if that legacy variable is present
   and require DOM_WALLET_PASSWORD_FILE. Rescan uses the common bounded,
   owner/inode/mode/single-link checked loader and wraps its live password in
   Zeroizing. The loader now trims its one permitted terminal newline in place,
   avoiding an additional freed plaintext String allocation.

4. Ten credential-bearing production shell entrypoints inherited `bash -x`,
   Rust backtrace settings and the caller's core-dump limit. They now turn off
   xtrace before any secret read, clear BASH_XTRACEFD, force both Rust backtrace
   controls off, and fail before secret handling unless `ulimit -c 0` succeeds.
   The closed-mainnet node also pins DOM_LOG=info rather than accepting a stale
   verbose filter that could place private operational metadata in durable logs.

Reviewed boundaries

- Recovery passwords, TPM owner authorization, operational state passwords,
  RPC bearer tokens and proving material remain file-backed and are passed only
  by non-secret path arguments.
- Wallet/TPM binaries print public commitments and identifiers, not plaintext
  credentials. Their error variants do not embed the captured secret values.
- RPC clients retain bearer material in Zeroizing storage; request errors do
  not serialize headers. Authenticated responses remain `Cache-Control:
  no-store` and loopback-only under the separate transport boundary.
- Finalized-burn/deposit reports contain public transaction/proof identities,
  commitments and redacted failure labels, not wallet recovery or bearer data.

Residual limits

JavaScript strings and the existing NodeConfig String cannot promise immediate
physical erasure of every allocator copy. The corrected launch boundaries keep
those values out of persistent interfaces and disable core dumps; Rust-held
long-lived node configuration already zeroizes password/token fields on drop.
A same-UID process with arbitrary ptrace/code-execution capability remains an
operating-system account compromise, outside an application-only guarantee.
