USDOM stage 372 — captured snapshot and TPM submission publication boundary

captured envelope. The TPM authority bootstrap uses this API, so filesystem
identity validation, decryption, rollback-seal validation and decoded wallet
state all refer to the same bytes without a pathname reopen.

The private-burn submitter now reads the encrypted TPM credential once. The
bootstrap evidence hash and TPM authorization restoration consume that same
buffer. This removes the substitution window between credential evidence
validation and use.

now use the shared writer anchored to a retained owner-only parent descriptor.
The seal keeps atomic replacement semantics; the receipt keeps no-clobber
semantics. Both are reread and checked after publication. The node declares
the writer as a direct optional operator dependency, and Cargo.lock was
updated offline before locked verification.
