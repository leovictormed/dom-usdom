Finding
=======

The readiness file contains the unguessable loopback capability used to reach
credential-bearing providers. The proxy created it safely, while removal was
left to each parent executor's temporary-directory cleanup. A standalone crash
or orderly proxy exit could therefore leave a stale capability pathname until
its parent cleaned the workspace.

Correction
==========

After writing and fsyncing readiness, the proxy validates and records the file's
device, inode, owner, mode and link count. Its shared close/exit cleanup removes
the pathname only when lstat still identifies that exact regular inode. A
substituted file or symlink is left untouched. If publication itself fails after
creation, the still-open descriptor is compared with the pathname and its own
matching inode is removed before the error escapes.
