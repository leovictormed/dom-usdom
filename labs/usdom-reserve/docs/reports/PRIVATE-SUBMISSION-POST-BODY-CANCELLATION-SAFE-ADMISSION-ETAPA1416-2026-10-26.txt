USDⓄM — ETAPA 1416
Private submission post-body, cancellation-safe admission
Date: 2026-10-26

Scope
- Authenticated POST /usdom/v4/transfer/submit/v1
- Authenticated POST /usdom/v4/burn/submit/v1
- HTTP body delivery, proof-worker admission, client cancellation, and bounded concurrency

Finding (material availability defect)
The shared tower ConcurrencyLimitLayer(1) wrapped extraction of the JSON body as well as native proof work. An authenticated client that slowly delivered a body could therefore occupy the sole transfer/burn proof-worker admission without submitting any complete request. The ordinary 30-second timeout limited duration per request but still allowed repeated starvation. In addition, tying the admission lifetime to the HTTP request future would allow a disconnected client to release admission while already-started native work continued.

Correction
- Replaced pre-extraction proof admission with a dedicated one-permit semaphore acquired with try_acquire_owned only after bounded JSON extraction and canonical payload decoding.
- Moved the acquired permit into a spawned Tokio submission task. Once native work starts, disconnecting or cancelling the HTTP request no longer releases admission before that work ends.
- Added a distinct four-permit body-delivery admission before extraction. Slow authenticated bodies remain bounded but cannot consume the proof-worker permit.
- Transfer and burn continue sharing the same proof-worker semaphore because they use the same native proof-verifying runtime.
- Capacity exhaustion remains fail-fast and retryable (HTTP 503) rather than accumulating a queue.
