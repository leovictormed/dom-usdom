Checkpoint V6 closure-aware Rust migration — Stage 1080 — 2026-10-26

Finding
The host-reference V2 executor still decoded UDCPST05 and did not bind the
authenticated issuance-closure bit. Its calls into native package validation
also omitted the newly required closure policy. Candidate-V2 source APIs still
accepted an absent closure policy, allowing a V6 source boundary to be built
without the immutable Ethereum closure identity.

Corrections
- `execute_checkpoint_extension_v2_with_witnesses` decodes only UDCPST06 and
  rejects V5 framing.
- The exact target `total_issued`, `total_burned` and `issuance_closed` are
  compared to the independently executed state at the checkpoint target.
- Candidate-V2 reference execution and source builders require an explicit
  `StaticIssuanceClosureTrustPolicy`; both block-verification paths receive the
  authenticated policy. The node fails closed when its V2 runtime lacks it.
- Current V2 runtime/export fixtures use schema 3 plus an exact closure policy.
- V6 outer-chain regressions use UDCSTN04 economic/closure fields and the V6
  validator. Historical V4/V5 readers remain only in explicit compatibility
  tests.
- Fixtures that materialize current static Ethereum policies now use a valid,
  strictly increasing fork schedule. The sole remaining default fork schedule
  is an intentional regtest network-identity test that does not construct a
  static policy.
