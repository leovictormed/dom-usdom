Concrete defects corrected
===========================

1. The Rust outer proof host already constructs and validates the 551-byte
   `UDCPST06` statement, but published it under `checkpoint-statement-v5.bin`.
   Most shell launchers and downstream consumers retained that old path, while
   the current submission SDK and observer used `checkpoint-statement-v6.bin`.
   A freshly produced proof could therefore not traverse the current pipeline.
   All active producers, snapshots, job consumers, packagers, exporters,
   finalized-burn inputs and submission readers now use the V6 path.

2. The capacity collector read the old V5 path, admitted at most 550 bytes and
   later hard-coded exactly 550 bytes. It would reject the canonical 551-byte
   closure-aware statement and accept the legacy length at that boundary. It now
   reads only the V6 path with an exact 551-byte bound and rechecks that length.
   A negative regression supplies a legacy 550-byte file at the V6 path and
   proves rejection.

3. `privateArtifact` accepted a `minimum` option but discarded it and always
   passed minimum 1 to the descriptor-bound reader. The new exact statement
   bound exposed this latent API error. It now propagates both caller-supplied
   minimum and maximum bounds.

4. The capacity E2E executor imported `parseCheckpointStatementV5`, which is not
   exported by the current submission SDK. It now uses the V6 parser. The EVM
   integration fixture also uses V6 and supplies the authenticated economic
   totals and issuance-closure flag.

5. Two structural evidence gates still looked for `CheckpointStatementV4` even
   though current production source is V6. They now require V6 and the outer
   boundary checker requires `validate_checkpoint_outer_chain_v6`. Historical
   V4/V5 decoders and tests remain only where explicitly needed to prove version
   separation and replay rejection.
