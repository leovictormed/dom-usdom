USDOM — private RPC catalog credential boundary — stage 574
Date: 2026-10-23

Finding
=======
Three runtime RPC catalogs carried complete provider URLs, including reusable API
credentials, directly in process environment values. Environment inheritance,
service inspection and crash collection could therefore preserve those
credentials. The deployment and Safe recovery executors additionally resolved
those URLs into `cast --rpc-url` arguments, exposing them through process argv.

Correction
==========
- All 23 JavaScript consumers of the mainnet-preflight, checkpoint-finalized and
  checkpoint-ratification catalogs now accept only the corresponding `_FILE`
  environment variable. Supplying the former literal variable is a fatal error.
- `sdk/runtime-secret-json.mjs` accepts only an absolute, canonical path in a
  current-user owner-only parent. The file must be a current-user, regular,
  non-symlink, single-link, exact-mode-0600, bounded file. It is opened with
  O_NOFOLLOW/O_CLOEXEC and its device, inode, size, timestamp, owner, mode and
  link count are checked around two positional reads. Byte buffers are cleared.
- Nine shell entrypoints now document/require the path-only interface and disable
  inherited xtrace, Rust backtraces and core dumps before catalog access.
- The two `cast` executors no longer materialize real provider URLs in shell
  variables or argv. A short-lived localhost proxy captures the secure catalog
  once and gives `cast` random, ephemeral loopback capability URLs. The proxy
  denies redirects, accepts only the Ethereum methods required by the ceremony,
  bounds requests to 4 MiB and responses to 32 MiB, enforces a 120-second
  upstream deadline, validates JSON-RPC response identity/envelopes and returns
  generic failures without provider details. Its owner-only readiness file
  contains only ephemeral loopback URLs.
- The obsolete resolver that printed credential-bearing URLs was removed.
- Residual pre-sign/broadcast source re-resolution calls were removed. Executors
  now verify that the captured in-memory proxy and its recorded PID remain live;
  the provider set cannot change underneath the ceremony after capture.

Validation
==========
- `bash -n labs/usdom-reserve/scripts/*.sh`: pass.
- No production reference remains to the deleted URL-output resolver or its
  removed shell state.
- No usage text still instructs operators to put a catalog literal in the
  environment.
- `git diff --check` over the changed stage-574 surface: pass.
- The complete affected Node campaign was rerun in stage 582 with the pinned
  Node 24.19.0 runtime: 162/162 tests pass. No heavy Cargo/Foundry job was
  started while the real RandomX proof is active.

Operational effect
==================
Persistent provider credentials now reside only in explicitly provisioned
owner-only files and transient process memory. Environment values disclose only
the path. Process argv for `cast` discloses only a random localhost endpoint
that expires when the executor exits. This does not turn provider URLs into
signing keys and does not alter any consensus, release, deployment or fund fact.

No commit, push, deploy, signature, broadcast or fund action was performed.
